# Benchmarks

This page covers three things: how the lab measures buff quality, what it measured, and the public benchmarks it used to choose models. The raw results behind every number are in [`benchmarks/`](benchmarks/), and each run's `report.html` shows every buff with its judge errors.

## How a buff is scored

Every buff, whichever method wrote it, goes through the same evaluation panel after it is finished. The panel never gates a buff and never sees which method wrote it.

- **Blind Claude judge** (`claude-opus-5-5`, high effort, `bbl/judge.py`). It reads the match facts and the target-language card, plus the style sheet, glossary and press-verified name forms. It never sees the English source. It lists errors MQM-style, each with a span, a category (grammar-case, grammar-agreement, terminology, name-form, fluency-translationese, accuracy-facts, style-register, spelling-diacritics, ui-fit) and a severity. It also scores grammar, naturalness, terminology, faithfulness and engagement from 1 to 5.
- **Approve** means no major or critical errors.
- **MQM penalty** weights errors 1 (minor), 5 (major) and 10 (critical). Lower is better; 0 is a clean card.
- **Second-vendor judge** (Gemini). It scores the same card to check for same-family bias. It answered for only some buffs because of overload errors, so its counts have smaller totals.

The judge follows the GEMBA-MQM recipe: errors with spans first, scores second. GEMBA-MQM reached 96.5% system-level pairwise accuracy on WMT23 without references, and its authors warn against using it as the only evidence ([arXiv 2310.13988](https://arxiv.org/abs/2310.13988)). WMT25 used two independent LLM judges for its automatic ranking. This lab uses two judges from different vendors for the same reason.

## The test set

Three simulated matches with real Wikidata entities ([`samples/events/`](samples/events/)), two live moments each, three languages: 18 buffs per method.

| Match | Sport | Moments |
|---|---|---|
| Latvia vs Canada | ice hockey | a tripping minor puts Latvia on the power play (prediction); Merzļikins has made 31 saves (poll) |
| Estonia vs Italy | football | VAR awards Estonia a penalty with Donnarumma in goal (prediction); Karol Mets at half-time (poll) |
| Žalgiris vs Real Madrid | basketball | Francisco's three cuts the gap to three (prediction); Campazzo's 7 assists at half-time (quiz) |

## Results

### Quality: 18 buffs per method

| Method | What it is | Approved (Claude judge) | Major + critical errors | Approved (Gemini judge) |
|---|---|---|---|---|
| A | Today's Translate button: English buff, then JIL's translate prompt | 5/18 | 30 | not run |
| B | Today's `sports_native` prompt, one call | 7/18 | 21 | 6/11 |
| C | Native-first pipeline: locale pack, case tables, validators, judge-driven repair | 17/18 | 3 | 7/10 |
| D | C plus press-verified names, five specialist reviewers and an orchestrator | 17/18 | 1 | 15/17 |

A and B come from [`benchmarks/today-A-B`](benchmarks/today-A-B/). B, C and D come from [`benchmarks/round2-B-C-D`](benchmarks/round2-B-C-D/). C and D were generated by `claude-opus-5-5`. The lab's README says the A and B baselines used the same model; the saved results don't record the model, and the default baseline in `.env.example` is `claude-sonnet-5-5`, so treat that as unconfirmed.

Lithuanian is the hardest language for every method. Across both runs, 14 of its 30 major errors are name forms: Lithuanian adds endings to foreign names and keeps their original letters, as in Merzļikinas. In Latvian (13 of 24) and Estonian (10 of 16) most major errors are sport terminology instead, such as the football verb used for a hockey goal. Those two causes line up with the two biggest additions in the new prompt: the name case tables and the glossary. Translation does least damage in Estonian, but even there it gets half the cards wrong.

### Run-to-run variance

Method B appears in both runs, with the same prompt and moments. It was approved 8/18 times with 15 major errors in the first run, and 7/18 with 21 in the second. Expect differences of that size between runs of the same method, so a single 18-buff run shows direction, not a precise rate.

### Latency and cost (method D, one live buff)

From `tools/timing.py`, writing plus review, with no evaluation panel ([`benchmarks/latency`](benchmarks/latency/)):

| Reviewers | Language | Write | Review team | Total | Cost |
|---|---|---|---|---|---|
| All Claude | lt | 13.2 s | 4.0 s | 17.4 s | $0.050 |
| All Claude | lv | 11.0 s | 2.2 s | 13.5 s | $0.036 |
| All Claude | et | 10.5 s | 2.1 s | 13.5 s | $0.036 |
| Gemini native-ear | lt | 12.5 s | 52.3 s | 65.0 s | $0.031 |
| Gemini native-ear | lv | 11.6 s | 30.8 s | 42.8 s | $0.028 |
| Gemini native-ear | et | 11.7 s | 199.9 s | 212.7 s | $0.028 |

The deterministic validators take 0.25 to 1.1 seconds. With Claude reviewers a live buff takes a median of 13.5 seconds; the Gemini reviewer saves under 2 cents and can add minutes when the service is overloaded, so it stays off the live path. The live app uses Claude for every reviewer for this reason.

Costs use $4 / $20 per million input / output tokens for Opus 5.5, with cache writes at 1.25x and cache reads at 0.05x input. The writer's system prompt (about 2.5k tokens) is cached, so the second buff in the same match and language pays about a twentieth of the input price for it.

## Public benchmarks used to choose models

No public benchmark tests short sports copy in these languages, so the lab built its own test above. These public results shaped the model choices and the next steps. Full notes are in [`research/02-tools-models-data.md`](research/02-tools-models-data.md) and [`research/03-methods-and-quality-loops.md`](research/03-methods-and-quality-loops.md).

**Estonian: EKI leaderboard.** The Institute of the Estonian Language runs a native Estonian leaderboard ([data](https://github.com/keeleinstituut/leaderboard-data-ui), 101 models, checked 2026-11-11). Its Keelenõu (240 language-norm questions) and idioms tasks are the closest public test of correct, natural Estonian.

| Rank | Model | Overall | Keelenõu | Idioms |
|---|---|---|---|---|
| 1 | Claude Fable 5.2 | 74.6 | 74.4 | 75.0 |
| 14 | Claude Opus 5.5 | 63.7 | 68.8 | 62.0 |
| 30 | Claude Sonnet 5.5 | 52.1 | 62.5 | 47.3 |
| 90 | Gemma 3 27B | 25.8 | 36.7 | 19.3 |

The pipeline writes with Opus 5.5 (rank 14). Fable 5.2 ranks first, which is why "best model per language" is on the next-steps list. The gap between Sonnet 5.5 and Opus 5.5 also suggests part of A and B's weakness in the live runs comes from the model, not only the method.

**WMT25, English to Estonian.** The WMT25 human evaluation found a 26-point spread between frontier models on English to Estonian (Gemini 2.5 Pro 78.8, Claude 4 53.0, human reference 83.1). WMT25 did not run English to Lithuanian or Latvian, so there is no equivalent table for them ([WMT25 findings](https://steinst.is/files/2025_wmt_sharedtask.pdf)).

**Glossaries in the prompt.** The WMT25 terminology task was won by systems that put the glossary in the prompt and asked the model to adapt each term's morphology ([ACL Anthology](https://aclanthology.org/2026.wmt-main.112.pdf)). Hard lexical constraints break inflection in morphologically rich languages. This is the basis for stage 3, the locale pack.

**Grammar ranking: MultiBLiMP.** TildeOpen-30b, an open-weight model built for these languages, scores 99.7% (lt), 99.1% (lv) and 98.3% (et) on the MultiBLiMP grammaticality test, against 95.3%, 91.6% and 92.0% for Gemma 2 27B. It is a base model, so the proposed use is ranking several drafts rather than writing them.

**Open models on Baltic translation.** A NoDaLiDa / Baltic-HLT 2025 paper scored English to Lithuanian, Latvian and Estonian on FLORES-200 with COMET: DeepL 0.92 to 0.93, GPT-4o 0.91 to 0.92, Gemma 2 27B 0.88 to 0.89 ([ACL Anthology](https://aclanthology.org/2025.nodalida-1.30.pdf)). Those models are from 2024 and COMET scores translation from a source sentence, which the native-first pipeline doesn't have.

## Limits

- The Claude judge reads the same style sheet as C and D, which can favour them. The Gemini judge offsets this partly. Native raters are the real test; the protocol is in `research/03`.
- 18 buffs per method from three simulated matches show the direction, not a benchmark, and the variance section above shows how much a rerun can move.
- The example buffs and several style rules are research drafts that no native speaker has reviewed yet.
- The Gemini judge answered for 38 of 54 buffs in round 2; the rest hit overload errors.

## Reproduce

```bash
uv sync
uv run python -m bbl.cli run samples/events/*.json --langs lt,lv,et --arms A,B,C,D
uv run python -m bbl.analyze out/run-<stamp>/results.json
PYTHONPATH=. uv run python tools/timing.py out/timing.json
```

Method B reads JIL's private `sports_native` prompt from `../backend/`, so outside the JIL repository it needs that file in place. A full four-method run makes about 280 model calls.
