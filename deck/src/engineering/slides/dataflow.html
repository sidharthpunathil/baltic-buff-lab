ARM D: REQUEST FLOW FOR ONE BUFF

Live buffs pay only for writing and review; name work happens before kickoff

PRECOMPUTE · per event

1. Resolve teams + players on Wikidata
2. Case tables per language
3. Apply press overrides + Tēzaurs
4. Cache, native editor checks once

LIVE · per moment

5. Assemble prompt: style + glossary(sport) + names + 6 examples
6. Generate BuffDraft (structured output)
7. Validators, ms
8. Five reviewers in parallel

DECIDE

9. Orchestrator: dismiss, block or advise
10. Routed repair, max 2 rounds, re-run only affected reviewers
11. Proposal + English gloss + decision log to the operator

The evaluation panel (fresh Claude judge + Gemini) only runs in the lab and in an offline nightly job. It never gates a live buff.

Steps 1 to 4 run once per event at event creation, so the live path pays nothing for Wikidata, Tēzaurs or press lookups.
